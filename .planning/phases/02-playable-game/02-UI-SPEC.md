## Spacing Scale

Standard 8-point scale. All values are multiples of 4.

| Token | CSS Property | Value | Usage |
|-------|-------------|-------|-------|
| xs | `--space-xs` | 4px | Grid gap between cells |
| sm | `--space-sm` | 8px | Button internal padding (vertical) |
| md | `--space-md` | 16px | App container padding; button horizontal padding |
| lg | `--space-lg` | 24px | Gap between title and board |
| xl | `--space-xl` | 32px | Gap between board and overlay content |
| 2xl | `--space-2xl` | 48px | App top/bottom padding on larger viewports |
| 3xl | — | 64px | Not used in Phase 2 |

Exceptions:
- `--cell-size: 112px` — board cells (3 cells × 112px + 2 gaps × 4px = 344px, within 360px board max). Touch target 112px far exceeds 44px minimum.
- `--board-max: 360px` — fixed board maximum width (D-08)

## Color

60/30/10 split. Game-specific tokens (`--color-x`, `--color-o`) are outside the
60/30/10 framework — they appear only within board cells and together make up the
full accent band.

| Role | Token | Value | Usage |
|------|-------|-------|-------|
| Dominant (60%) | `--color-bg` | `#F9FAFB` | App background; empty cell fill |
| Secondary (30%) | `--color-grid` / `--color-text` | `#1E293B` | Grid lines (CSS Grid gap reveal); app title; overlay background |
| Accent-X (5%) | `--color-x` | `#2563EB` | X marks in cells; empty cell hover tint (10% opacity) |
| Accent-O (5%) | `--color-o` | `#E85D04` | O marks in cells |
| Overlay text | `--color-overlay-text` | `#FFFFFF` | Text inside game-over overlay only |
| Destructive | — | none | No destructive actions exist in Phase 2 |

Accent reserved for:
- `--color-x` (#2563EB): X character rendered in board cells; hover tint on empty interactive cells
- `--color-o` (#E85D04): O character rendered in board cells
- These two colors appear nowhere else in Phase 2

Contrast check (WCAG AA minimum 4.5:1 for text):
- `#2563EB` on `#F9FAFB`: ~5.4:1 — passes AA
- `#E85D04` on `#F9FAFB`: ~4.6:1 — passes AA
- `#1E293B` on `#F9FAFB`: ~14.5:1 — passes AAA
- `#FFFFFF` on `rgba(30,41,59,0.92)`: ~12.1:1 — passes AAA

## Board Grid Implementation

From D-11: borders define the grid; no background fill on cells. Implementation
uses CSS Grid gap technique — the grid container background is `--color-grid`
and the gap reveals it as grid lines.

```
Board container: CSS Grid, 3×3
  grid-template-columns: repeat(3, var(--cell-size))
  grid-template-rows: repeat(3, var(--cell-size))
  gap: var(--grid-gap)           /* 4px — grid line width */
  background-color: var(--color-grid)   /* reveals as grid lines */

Cell:
  background-color: var(--color-bg)     /* hides grid bg except in gaps */
  display: flex; align-items: center; justify-content: center
  font-size: var(--font-size-display)   /* 40px marks */
  font-weight: 700
  cursor: pointer (empty + interactive only)
```

Cell states (four, each has distinct CSS class):
| State | Class | Appearance |
|-------|-------|------------|
| Empty, interactive | `.cell` | `--color-bg` bg; hover shows `--color-hover` tint |
| Occupied by X | `.cell.cell--x` | `--color-bg` bg; X rendered in `--color-x` |
| Occupied by O | `.cell.cell--o` | `--color-bg` bg; O rendered in `--color-o` |
| Empty, frozen (game over) | `.cell.cell--frozen` | `--color-bg` bg; no hover; `cursor: default` |

## Layout

From D-08, D-09: single centered column, flexbox, responsive. Primary focal point: the 3×3 board grid is the dominant visual element; the title and "Play again" button are secondary anchors.

```
body / #app-root:
  display: flex
  flex-direction: column
  align-items: center
  min-height: 100vh
  padding: var(--space-md)      /* 16px */
  background-color: var(--color-bg)

.game-container:
  display: flex
  flex-direction: column
  align-items: center
  gap: var(--space-lg)          /* 24px between title and board */
  width: 100%
  max-width: var(--board-max)   /* 360px cap */

Column order (Phase 2):
  1. App title (h1)
  2. Board (with game-over overlay when applicable)

Phase 3 will append:
  3. Engine speech bubble
  4. Session scoreboard
  5. New Game + Reset Scores controls
```

Responsive (from UI-06, D-08):
- Board: `width: min(var(--board-max), calc(100vw - 2 * var(--space-md)))` — fills viewport minus 16px padding each side below 360px
- Cell size stays fixed at `--cell-size: 112px`; board shrinks via grid container constraining the viewport, not by shrinking cells. If viewport is below 344px (3 cells + 2 gaps), a horizontal scroll is acceptable — the hard constraint is 320px minimum (UI-06)
- Minimum supported viewport: 320px (cells still display at 100px width at 320px viewport with 16px padding each side: `(320 - 32 - 8) / 3 ≈ 93px` — adjust `--cell-size` responsively if needed, see note below)

Responsive cell sizing note: at viewport widths below 360px, apply:
```css
@media (max-width: 360px) {
  :root {
    --cell-size: calc((100vw - 2 * var(--space-md) - 2 * var(--grid-gap)) / 3);
  }
}
```
This ensures cells scale down proportionally on narrow viewports (320px minimum per UI-06).

## Game-Over Overlay

From D-05, D-06, D-07.

The overlay positions absolutely on top of the board and dims it. The board remains
in the DOM and visible beneath the overlay (dimmed), but all cells have `pointer-events: none`.

```
.board-wrapper:
  position: relative     /* overlay anchor */
  width: fit-content

.game-over-overlay:
  position: absolute
  inset: 0
  background-color: var(--color-overlay-bg)   /* rgba(30,41,59,0.92) */
  display: flex
  flex-direction: column
  align-items: center
  justify-content: center
  gap: var(--space-xl)    /* 32px between outcome text and button */
  border-radius: 0        /* flush with board edges */
```

Overlay content:
1. Outcome text — `font-size: var(--font-size-display)` (40px), weight 700, `--color-overlay-text` (#FFFFFF)
2. "Play again" button — `font-size: var(--font-size-body)` (16px), weight 400, styled as pill/rounded button

## Component Inventory

All components live in `kiss-tictactoe-ui/src/` as Dioxus `#[component]` functions.

| Component | File | Props | Notes |
|-----------|------|-------|-------|
| `App` | `main.rs` | none | Root; owns `Signal<Game>` via `use_signal`; injects CSS |
| `Board` | `components/board.rs` | `game: Signal<Game>` | Renders 3×3 grid + overlay; handles cell click → `game.make_move()` |
| `Cell` | `components/cell.rs` | `pos: Position`, `content: Option<Player>`, `interactive: bool`, `on_click: EventHandler<Position>` | Single cell; handles its own hover state via CSS class |
| `GameOverOverlay` | `components/game_over_overlay.rs` | `status: GameStatus`, `on_play_again: EventHandler<()>` | Shown when `status != InProgress`; hidden otherwise |

State ownership: `Signal<Game>` lives in `App`, passed down. `Board` calls `game.write().make_move(pos)` on cell click. Dioxus re-renders derive the board display from `game.read().board()` and `game.read().status()`.

## Interaction Contract

| Interaction | Trigger | Response | Notes |
|-------------|---------|----------|-------|
| Player move | Click empty, interactive cell | Cell shows X; engine responds immediately (O placed); board re-renders | D-04: engine moves inside `make_move` |
| Cell hover | Hover over empty interactive cell | `--color-hover` tint (`rgba(37,99,235,0.10)`) applied via CSS `:hover` | No hover on occupied or frozen cells |
| Game over | Win/draw detected after move | Board freezes (all cells get `pointer-events: none`); overlay appears | D-05 |
| Play again | Click "Play again" in overlay | `game` signal set to `Game::new()`; overlay disappears; fresh board shown | D-07 |

Timing: minimax on 3×3 is instant — no loading state, no delay animation (per REQUIREMENTS.md out-of-scope).
