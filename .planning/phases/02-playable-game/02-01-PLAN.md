## Phase Goal

**As a** player sitting at the desktop app, **I want to** click board cells and watch the engine answer each move until a win, loss, or draw, **so that** I can play a complete game of tic-tac-toe against an engine that never loses.

(Derived verbatim-in-substance from the ROADMAP Phase 2 goal: "A human can sit down and play a complete tic-tac-toe game — clicking cells, watching the engine respond, and seeing a win, loss, or draw declared — all within a responsive Dioxus desktop UI.")

<objective>
Vertical slice 1 of the playable game: a human clicks a cell in the Dioxus desktop window, the engine places X, replies with an optimal minimax O in the same `make_move` call, and the board re-renders. Cells that are occupied, or all cells once the game is over, stop accepting clicks.

Purpose: After this plan the game is playable end to end (no game-over banner yet — that is slice 2 in plan 02-03; correctness proof of the AI is plan 02-02).
Output: Engine public API (Game, Position, Player, Board, GameStatus, MoveResult, MoveError, detect_status), engine integration test, Board and Cell Dioxus components, base CSS tokens and grid.

Task ordering note (MVP mode): Task 1 is the failing end-to-end test on the engine public API (Dioxus desktop UI has no automatable E2E harness in this project). Engine and UI are split across Tasks 2 and 3 only because of task sizing (10+ files in one task exceeds the per-task context budget); the plan as a whole is the vertical slice.
</objective>
